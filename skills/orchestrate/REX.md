# Rex terminal operations for Codex

Use these operations throughout the shared orchestration loop, including its linked procedures. A Herdr example of prompting, waiting, reading or answering means the corresponding operation here. Keep the same dispatch preamble, phase model and effort, approval checks, worktree and recovery rules.

## Set up the run

1. Verify the inherited session and block together with `rex block inspect -s "$REX_SESSION" "$REX_BLOCK" --json`. Save its window ID. Use the full IDs for every operation, including after focus changes. Report an invalid or inaccessible target before creating lanes. Use the host's normal permissions for the Rex socket, Git and GitHub.
2. Require Codex as identified by current host metadata or the Codex signals in Setup step 3, and require the Codex CLI. For any other or unidentified host, stop with its name and explain that Rex orchestration currently supports Codex only. Do not select a different harness. Resolve the coordinator’s effective Codex home to an absolute directory (default `~/.codex`). Save it as WORKER_HOME and use its `sessions/` directory for SESSION_ROOT.
3. Use the shared PROJECT and K naming rules. Inspect Rex block labels across sessions with `rex ls --json` and `rex block ls -s SESSION --json` for each session, plus the registered and on-disk worktrees. Label the coordinator with `rex block rename -s "$REX_SESSION" "$REX_BLOCK" PROJECT-orch-K`. Read the tracker and perform the remaining common setup from step 5.

## Open and identify lanes

Open a placeholder per lane using `rex split -s "$REX_SESSION" -b ANCHOR --split=DIRECTION --ratio PERCENT --focus=false --keep-open --shell=none --label WORKER --json -- true`. Take the new PANE from `.block_ids[0]` and record ownership. Start right of the coordinator at 50 percent. Stack each subsequent pane below its predecessor, giving the new pane the rounded percentage `100 * (LANES-L+1)/(LANES-L+2)`. On an uncertain split result, inspect the layout and reconcile it before retrying.

To start a worker, split the lane's exited placeholder or exited prior worker, passing `-b PANE --split=right --focus=false --keep-open --shell=none --label WORKER -c WT --json -- env "CODEX_HOME=$WORKER_HOME" codex --no-alt-screen --model MODEL -c model_reasoning_effort=EFFORT` with the same session. Pass paths and options as individual arguments. Record the replacement block ID before closing the exited, run-owned old block with `rex block close -s SESSION OLD`. The replacement occupies its lane. An ambiguous replacement, unexpected process exit or failure to confirm ownership parks the lane.

Inspect the new pane with `rex capture -s SESSION -b PANE --trim --unwrap`. Handle visible startup dialogs under [Answer a dialog](ANSWER.md#answer-a-dialog). Once Codex accepts input, send the native `/status` command and read the **Session** UUID from the new response. Resolve its exact rollout filename suffix under SESSION_ROOT, require a unique readable file with matching `session_meta.payload.id`, and retain the path in SESSIONS. If creation is lazy, recheck after the first turn. A restart must yield a new UUID. Park if identity or the transcript cannot be established. Keep account and usage details out of reports.

## Drive the worker

- **Send.** Check that the pane is showing the expected Codex input or dialog. For an instruction, build DISPATCH and TASK as in [Worker](WORKER.md#dispatch-preamble). Record the transcript end position before submission (or the beginning for a newly created first-turn transcript). Send the entire prompt as one bracketed paste with `rex send -s SESSION -b PANE -- TEXT`, enclosing the literal text between ESC `[200~` and ESC `[201~`. Reject embedded control characters except tabs and newlines. Confirm the paste reached the editor, then submit with `rex send-key -s SESSION -b PANE enter`. Native slash commands use plain text and Enter. Reconcile the visible pane and transcript before retrying any uncertain delivery.
- **Wait and read.** Monitor all busy lanes independently. Inspect each pane for pending dialogs while following complete JSONL records appended to its own transcript. Bind the submitted prompt to its new user message and `event_msg` / `task_started` turn ID. Accept only the matching `task_complete` after that submission. Read its `last_agent_message` or the visible reply; an old reply, silence or process exit cannot advance the lane. Recheck after 15 seconds for resumed work and apply the shared BUSY check for background workers. A partial final line waits for more bytes. A missing turn, aborted turn or unreadable required evidence must be reconciled or parked. Keep servicing other lanes during waits.
- **Answer.** Inspect the current visible controls. Apply [Answer the worker](ANSWER.md) before sending a displayed key with `rex send-key`. Capture again after each submission. A blocked or parked lane keeps its pane and worktree for inspection.
- **Show phase.** Use `rex window rename -s SESSION WINDOW TITLE` with the shared busy-lane phase list.
- **Stop and restart.** Retain the transcript, send native `/exit` to the idle worker and wait for its child exit in the background with `rex wait --for 30s -s SESSION PANE`. Continue servicing other lanes. On a timeout or nonzero exit, inspect the pane and `rex block call -s SESSION -b PANE process`. Park if a clean exit cannot be confirmed. Use this wait only for process exit. Start a fresh worker in its lane as above. At run shutdown close only idle blocks created by this run. Keep parked blocks open.
